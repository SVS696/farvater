# Разработка Фарватера

Перед изменением выберите режим и прочитайте соответствующую страницу
[документации](docs/README.md). [Архитектура](docs/architecture.md) указывает основные
модули; публичная совместимость описана в [матрице проверок](docs/validation.md).

## Окружение

Нужен Python 3.11+. Из корня checkout:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install --require-hashes -r requirements.txt
```

Для интеграционных тестов локального узла загрузите проверенное ядро:

```sh
.venv/bin/python tools/download_core.py --destination "$HOME/.local/share/farvater/core"
export FARVATER_TEST_CORE="$HOME/.local/share/farvater/core/sing-box"
```

## Проверки

```sh
.venv/bin/python -m unittest discover -s src -p 'test_*.py'
.venv/bin/python -m unittest discover -s install -p 'test_*.py'
.venv/bin/python -m unittest discover -s tools -p 'test_*.py'
git diff --check
```

Сначала запускайте проверки изменённого модуля, затем нужные наборы.
CI выполняет эти три набора на Linux и macOS. Платформенные пропуски
не подтверждают работоспособность пропущенной функции. Тесты с имитацией
системных команд не заменяют установку и проверку трафика на целевой ОС.
Для правки только текста достаточно проверить ссылки, команды по исходнику и diff.

## Изменения

Описывайте конкретное поведение до и после, затронутый режим и результаты
проверок. Изменения инструкций должны сохранять ограничения и способы
восстановления. Для правок маршрутов, PF, DNS, служб и привилегий используйте
выделенный стенд с отдельным доступом; заранее определите возврат состояния.

В репозиторий входят исходники и обезличенные примеры. Реальные политики,
сертификаты, ключи, журналы, архивы и каталоги состояния остаются вне Git.
Лицензионные уведомления сторонних компонентов сохраняйте вместе с ними.

Техническая сверка функций: [карта маршрутов](docs/reference/panel-route-map.md) и [машиночитаемый реестр](docs/scenario-coverage.json). Пользовательский вход — [разделы панели](docs/scenario-coverage.md).
