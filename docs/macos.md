# Farvater на macOS

Для первой установки начните с [пошагового сетапа](setup.md). Здесь описаны параметры и особенности macOS.

Farvater можно установить на Mac mini как самостоятельный узел: локальный `sing-box` применяет правила выходов, обслуживает DNS и SOCKS/HTTP, а веб-панель управляет этим ядром. Для **системного VPN и LAN-шлюза** нужен отдельный привилегированный режим из [инструкции по шлюзу](macos-gateway.md). Запуск локального proxy/DNS-узла сам по себе не переводит трафик macOS или всей локальной сети в туннель.

Нужны macOS на Apple Silicon или Intel, Python 3.11 или новее и учётная запись обычного пользователя. Из распакованного релиза:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install --require-hashes -r requirements.txt
.venv/bin/python tools/download_core.py --destination "$HOME/Library/Application Support/Farvater/core"
.venv/bin/python tools/local_node.py init --core "$HOME/Library/Application Support/Farvater/core/sing-box" \
  --probe-domain example.com --probe-url https://example.com/
.venv/bin/python tools/local_node.py serve
```

Загрузчик сверяет официальный архив `sing-box` версии 1.14.1 с закреплённым SHA-256 и сохраняет проверенный бинарник в закрытом каталоге. Инициализация спрашивает адрес DNS, доступный **этому Mac**, а также логин и пароль администратора панели. Пароль вводится без показа, в `auth.json` остаётся только хеш. До записи локального узла конфигурация проверяется настоящим бинарником. Начальный черновик состоит из прямого выхода и указанного DNS; существующие серверные правила он не импортирует.

Первый запуск `serve` должен оставаться в отдельном терминале. В другом терминале проверьте `.venv/bin/python tools/local_node.py status` и запустите панель:

```sh
.venv/bin/python tools/run_panel.py --mode local-node
```

Откройте `http://127.0.0.1:18081/login`. Панель принимает соединения только на `127.0.0.1`, использует тот же закрытый каталог состояния и связывается с узлом по Unix-сокету с правами 0600. Порт панели можно изменить `--port`; у локального узла отдельные `--dns-port`, `--proxy-port`, `--api-port` при `init` (по умолчанию 5301, 2081, 9091). Не запускайте эти команды через `sudo`. В режиме `local-node` разделы нативных VPN-серверов, прозрачного Linux LAN-входа, AdGuard и маршрутизации Linux показывают отказ, а не вызывают Linux-службы.

После проверки запустите supervisor при входе пользователя:

```sh
.venv/bin/python tools/local_node.py install-agent
.venv/bin/python tools/local_node.py status
```

Команда ставит собственный `~/Library/LaunchAgents/com.farvater.local-node.plist` без секретов и регистрирует его в пользовательском `launchd`. Он работает независимо от веб-панели и запускается снова при входе. Если при перезапуске остаётся неподтверждённое применение, supervisor возвращает предыдущую конфигурацию до запуска ядра. Действующее применение требует подтверждения за 120 секунд; истечение срока возвращает прежнюю ревизию. Потеря HTTP-ответа не означает, что действие не было выполнено: сначала перечитайте `/changes` или `local_node.py status`, не отправляйте применение повторно вслепую. Остановленная панель не останавливает ядро.

Для клиента в частной сети можно отдельно включить аутентифицированный SOCKS-вход: при `init` задайте `--lan-listen` как **конкретный** адрес Mac из RFC1918, `--lan-port` и `--lan-user`. Пароль клиентского SOCKS запрашивается без отображения и хранится только в закрытых настройках узла. Этот вход не включает маршрутизацию всего LAN, DHCP, системный DNS или общий доступ в Интернет. Разрешайте к порту только нужных клиентов в сетевом экране. Сам DNS узла по умолчанию доступен только с `127.0.0.1`; его нужно явно указать клиенту локально.

Проверка пути при применении делает реальные DNS-запрос и SOCKS→HTTP(S) запрос к выбранным `--probe-domain` и `--probe-url`. Выбирайте подконтрольный тестовый адрес, который должен отвечать HTTP 200 или 204; не вводите URL с логином, токеном или query. Эта проверка подтверждает путь локального proxy/DNS-узла, **не** системный TUN и не маршрутизацию LAN. Полная приёмка шлюза требует отдельного клиента и проверки DNS, TCP, UDP и восстановления маршрутов на изолированном Mac; см. [режим шлюза](macos-gateway.md).

Закрытое состояние находится в `~/Library/Application Support/Farvater` с правами 0700; `auth.json`, `policy.json`, конфигурация, журнал и настройки узла имеют права 0600. Можно выбрать другой абсолютный путь через одинаковый `--state-dir` для `init`, `serve`, `status` и `run_panel`. Не переносите этот каталог, приватные ключи, пароли и экспорты политики в публичный репозиторий.

Есть и отдельный режим **панели для сервера Linux**: `.venv/bin/python tools/run_panel.py --mode remote` (это режим по умолчанию). После входа на `/server/access` задайте адрес, SSH-порт, пользователя и путь к уже существующему ключу либо используйте SSH-agent. Транспорт требует заранее подтверждённый ключ сервера (`StrictHostKeyChecking=yes`) и не принимает новый ключ автоматически. Пароль `sudo` при необходимости читается через форму, не передаётся в аргументах процесса; ошибочный ответ меняющей команды не вызывает автоматический повтор. Этот режим управляет сервером через SSH и не заменяет локальный узел Mac.
