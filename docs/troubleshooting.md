# Диагностика

Если вы пока не понимаете, какой компонент не работает, начните с симптома.
Открывающаяся панель, работающий VPN и доступный сайт — разные проверки.
Для красных карточек есть [разбор мониторинга](panel-monitoring.md#пример-красная-dns-карточка):
сначала отличите свежий отказ от отсутствия данных.

Проверяйте по порядку: процесс → доступ к панели → DNS → прокси → следующий узел.
Сохраняйте точное сообщение ошибки, режим и версию выпуска. Перед публикацией
журналов удаляйте ключи, пароли, токены, приватные адреса и содержимое конфигураций.

| Симптом | Что проверить | Дальнейшее действие |
|---|---|---|
| Не открывается локальная панель | Работает ли `tools/run_panel.py`, правильный ли порт | Открыть адрес из вывода команды на той же машине; по умолчанию `127.0.0.1:18081` |
| Панель доступна, узел не отвечает | `tools/local_node.py status`, вывод терминала `serve` | Проверить путь к ядру и одинаковый `--state-dir` у процессов |
| Адрес работает, домен — нет | DNS-сервер узла и запрос на порт 5301 | Проверить доступность указанного при `init` DNS и правило его маршрута |
| Прокси не отвечает | Запрос через `socks5h://127.0.0.1:2081` | Проверить ядро и выбранный выход отдельно от настроек приложения |
| Цепочка перестала работать | SSH/туннель и доступность следующего узла | Проверить каждый переход отдельно; восстановить транспорт |
| Изменения исчезли | Статус временного применения | При истечении срока подтверждения возвращается прежняя конфигурация |
| Удалённая панель не соединяется | SSH-ключ, ключ хоста, пользователь и права | Исправить причину SSH-ошибки; сохранить проверку ключа хоста |
| Linux-установщик отказал | Сообщение `check`, зависимости, занятые порты и существующее состояние | Устранить конкретный конфликт по [инструкции](linux.md); проверить повторно до `apply` |

## Linux-службы

На установленном сервере:

```sh
systemctl status okopy-candidate.service okopy-panel.service \
  infrastructure-recovery-ui.service infrastructure-recovery-https.service
```

Если панель недоступна, отдельно проверьте административную сеть, HTTPS
и `/recovery/login`. Не восстанавливайте архив поверх рабочей установки только
ради диагностики. При частичной первой установке сохраните файлы и сообщение
ошибки: повторная установка рассчитана на пустые целевые пути.

## Экспериментальный шлюз Mac

Команды `status` и `rollback` выполняйте защищённой копией helper, как описано
в [руководстве шлюза](macos-gateway.md). При отказе восстановления используйте
физическую консоль и приватные журналы. Глобальный сброс PF или удаление
произвольных маршрутов может нарушить настройки других служб.

## Сообщить о проблеме

Для обычного бага укажите выпуск, ОС и архитектуру, режим узла, шаги,
ожидаемый и наблюдаемый результат. Приложите минимальный обезличенный фрагмент
ошибки. О сообщениях, содержащих уязвимости или секреты, см. [SECURITY.md](../SECURITY.md).
