# Правила, DNS, фильтрация и выбор выхода

## Зачем нужны правила и DNS

Правила отвечают на вопрос: «Куда отправить трафик этого сайта или устройства?».
Например, рабочий портал можно отправить через корпоративный VPN, а домашний
принтер оставить в локальной сети. Правила проверяются в порядке списка;
последнее выбирает путь для всего, что не совпало выше.

DNS переводит имя сайта в IP-адрес. VPN может работать, а внутреннее имя — нет,
если его спросили у публичного DNS. Поэтому правило выбирает **пару**: подключение
для трафика и DNS для имён. Сначала [создайте подключение](panel-connections.md),
затем назначайте его правилу. Для общего устройства панели см. [введение](panel-overview.md).

## Пример: один публичный сайт через VPN

Для примера нужен уже созданный Shadowsocks из выданной ссылки. Назовём его
«Мой VPN». Приложение должно обращаться к локальному входу Фарватера, например
SOCKS на порту 2081. Пример относится к публичным именам, не к рабочей сети.

1. В «DNS и фильтрации» добавьте профиль «DNS через Мой VPN», тип «DNS по TCP».
   Сервер `1.1.1.1`, порт `53`, «Через какой выход» — «Мой VPN».
   Начальный DNS не нужен, потому что сервер задан IP. Это публичный DNS
   [Cloudflare](https://developers.cloudflare.com/1.1.1.1/ip-addresses/), не обязательный
   компонент Фарватера; если он недоступен через ваш VPN, используйте DNS,
   который выдал поставщик подключения.
2. В «Правилах» добавьте «Проверка VPN». Назначение — обычный интернет, источник
   пустой, имена `example.com` и `api.ipify.org` двумя строками.
3. Выход — «Мой VPN», DNS — «DNS через Мой VPN», правило включено.
   Фильтрация наследуется; резерв для первого опыта не добавляйте.
4. Подготовьте проверку ниже **до** применения. В «Изменениях» проверьте весь
   пакет, примените временно, выполните проверку и подтвердите в срок.

### Как проверить выбранный путь

[Сервис ipify](https://www.ipify.org/) показывает адрес, с которого к нему пришёл
запрос. Для локального узла команды выполняются на машине с Фарватером:

```sh
# Обычный выход этой машины, без прокси curl
curl --fail --show-error --max-time 15 --noproxy '*' https://api.ipify.org
# Выход через Фарватер и правило для api.ipify.org
curl --fail --show-error --max-time 15 --noproxy '' \
  --proxy socks5h://127.0.0.1:2081 https://api.ipify.org
```

Запишите обычный адрес заранее. После применения второй запрос должен показать
адрес выхода вашего VPN. Если поставщик его сообщил, сравните с ним. В цепочке
с собственной второй машиной выполните первый запрос на ней: результат должен
совпасть с запросом через цепочку. Если обычный и VPN-выход имеют один адрес,
этот тест их не различает — нужен журнал/наблюдение на контролируемом выходе.

Отдельно проверьте `example.com` через тот же прокси. Открытие сайта доказывает
доступность, а сравнение адреса — выбранный выход тестового запроса. Эти проверки
не доказывают маршрут всех программ, IPv6 и UDP. При неверном результате верните
прежний пакет. После опыта удалите тестовый домен ipify из правила, если он больше
не нужен, и примените изменение.

### Если нужен внутренний рабочий сайт

DNS-адрес и доменную область получите у администратора корпоративного VPN
или из выданного профиля. Создайте DNS-профиль с этим адресом и выходом через
рабочее подключение. Для внутреннего имени выбирайте эту пару в рабочем правиле.
Для имени **самого VPN-сервера** оставьте независимый DNS, доступный до VPN.
Публичный `1.1.1.1` не знает ваши внутренние имена; не подставляйте его как универсальный
ответ. Неизвестные корпоративные адреса нельзя достоверно угадать по интерфейсу.

## Общий порядок изменения

1. Откройте нужный раздел и сохраните форму. Это меняет черновик.
2. В «Изменениях» проверьте **весь** пакет: применяются все сохранённые изменения,
   включая изменения других форм и вкладок.
3. Нажмите «Применить настройки». От начала применения отсчитываются 120 секунд.
4. Проверьте доступ к панели, нужное устройство, DNS и клиентский трафик.
5. Нажмите «Проверить и подтвердить». Если результат неверен — «Вернуть прежний пакет».
   Без подтверждения прежний пакет возвращается автоматически.

Сохранение черновика, временное применение и подтверждение — три разных действия.
После таймаута HTTP обновите состояние прежде, чем повторять действие.
При конфликте версии (409) перечитайте форму: другая вкладка могла изменить черновик.

## Вход, обзор и помощь

Войдите через `/login` с созданной при установке учётной записью. При неверном
пароле исправьте ввод; при 429 подождите минуту. Кнопка выхода завершает сессию.
Обзор показывает политику и снимок состояния. Недоступный или устаревший мониторинг
требует проверки источника снимков; отсутствие данных не означает исправность.
На страницах раскрывайте «О странице» и подсказки полей. Раздел помощи доступен
из навигации. Выбор темы меняет оформление, а не сетевую политику.

## Добавить или изменить правило

1. «Правила» → «Добавить правило» либо редактирование существующего.
2. Введите название и назначение. Для рабочих и специальных ресурсов выбирайте
   соответствующее назначение; одно только название поведение не меняет.
3. Задайте условия и выберите **оба** поля: выход и DNS.
4. При необходимости настройте резервные пары, фильтрацию и семейство адресов.
5. Включите правило, сохраните, проверьте конфликты и примените общий пакет.

| Условие | Пример | Что означает |
|---|---|---|
| IP источника | `192.168.77.20/32` | Одно клиентское устройство |
| Подсеть источников | `192.168.77.0/24` | Клиенты подсети |
| Пустой источник | — | Все устройства, видимые этому входу |
| Точное имя | `example.com` | Только это имя |
| Поддомены | `*.example.com` | Поддомены без самого `example.com` |
| IP назначения | `10.20.0.0/16` | Сеть назначения |
| Исключённое имя | `www.example.com` | Исключение точного имени; защита рабочих IP остаётся |

Для домена и поддоменов укажите две строки. Заголовок `# Группа` организует
список, не меняя маршруты. В редакторе доступны добавление сайта и группы,
поиск, раскрытие/сворачивание и текстовый ввод. Изменения списка относятся к черновику.
При работе через прокси исходный IP клиента может быть скрыт: проверяйте, может ли
выбранный вход сохранить условие устройства. Ошибку проверки такой области исправляют
изменением входа или условий, а не отключением проверки.

## Порядок, отключение, удаление и общее правило

Перемещайте обычные правила вверх/вниз, затем применяйте новый порядок.
Последнее правило «Весь остальной трафик» закреплено в конце и не удаляется.
В нём выберите выход и DNS для трафика без совпадения с правилами выше.
Отключение обычного правила сохраните в его форме. Удаление требует отдельного
подтверждения; после применения трафик обработают последующие правила.
Проверьте, что удаление рабочего правила не снимает необходимую защиту.

## Проверить домен до применения

На странице правил введите домен, при необходимости источник, протокол и порт.
Разбор показывает выбор по черновику. Это объяснение правил, а не измерение
реального DNS или трафика. После применения повторите клиентский запрос.
При конфликте пересекающихся условий проверьте порядок и область каждого правила.

## Дополнительные условия

Протокол TCP/UDP и порты ограничивают выбор выхода; при несовпадении проверяются
следующие правила. DNS выбирается по домену и устройству независимо от порта
будущего соединения. Для рабочих, специальных и DNS-only правил оставьте любые
протоколы и порты. DNS-only меняет разрешение имени, а не автоматически весь маршрут.

Запрет UDP на выбранных портах сохраняется для условия правила. Например,
запрет UDP 443 ограничивает HTTP/3; доступность HTTPS по TCP проверяйте отдельно.
Семейство адресов и особый DNS-ответ настройте в соответствующих полях формы.
Особый ответ проверяйте запросами нужного типа (A/AAAA и др.), а не только браузером.

## Добавить DNS

1. «DNS и фильтрация» → «Добавить DNS».
2. Задайте название, назначение и тип.
3. Заполните поля выбранного типа, сохраните.
4. Назначьте профиль правилу либо последнему правилу; примените пакет.
5. Проверьте ответ через DNS-вход узла и маршрут к DNS-серверу.

| Тип | Параметры и важная проверка |
|---|---|
| Сетевой UDP/TCP | Сервер без схемы и пути; порт по умолчанию 53 |
| HTTPS (DoH) | Сервер, порт (обычно 443), путь, SNI |
| TLS/QUIC | Сервер, порт (по умолчанию 853), SNI |
| DHCP | Интерфейс либо основное подключение; независимый IPv4 DHCP DNS |
| Системный | DNS из ОС узла; проверить отсутствие зависимости от самого узла |
| Hosts | Строки `IP имя`; назначать только известным именам, не общему маршруту |
| OpenVPN | Существующее подключение; отдельно разрешать DNS и поисковые домены от VPN |
| FakeIP | IPv4/IPv6 диапазоны; проверить совместимость входа и резервирования |

Если DNS-сервер задан именем, выберите независимый начальный DNS (bootstrap).
Если задан IP, начальное разрешение имени не требуется. Поле «Через какой выход»
задаёт путь DNS-запросов отдельно от маршрута прикладного трафика.
Не создавайте зависимость VPN → DNS → тот же VPN. Циклы обнаруживаются при проверке.
При смене типа прежние параметры заменяются. Hosts-записи можно скачать в `.hosts`
и вставить в аналогичное поле другой установки.

## Удалить DNS или выход

Откройте удаление записи: панель покажет ссылки из правил и других настроек.
Сначала замените эти ссылки, сохраните связанные формы, затем подтвердите удаление.
Используемая запись может блокировать удаление. Удаление меняет черновик;
работающий узел изменится только после применения.

## AdGuard и исключения

Требуется подключённый Linux-адаптер фильтрации. В локальном переносимом режиме
нельзя считать наличие формы подтверждением поддержки AdGuard.

1. Откройте фильтрацию; выберите «Фильтровать по умолчанию».
2. Добавьте списки блокировки/разрешения: название, URL, состояние.
3. Для временного отключения списка смените состояние; для удаления удалите строку.
   Без JavaScript новый список вводится в дополнительных полях, удаление — очисткой URL.
4. Дополнительные правила вводите по одному на строку; область клиентов задавайте
   в общих правилах, модификаторы `client`/`ctag` здесь не используются.
5. Сохраните и примените. Проверьте блокируемое имя и разрешённое исключение.

В отдельном общем правиле доступны наследование, включение и отключение AdGuard.
Назначенный правилу DNS сохраняется. Для возврата измените фильтрацию и примените
или верните ещё неподтверждённый пакет.

## Резервные пары и автоматика

1. В правиле задайте основной выход/DNS и резервные **пары** в нужном порядке.
2. В общих порогах задайте число неудачных проверок подряд (1–20) и стабильное
   время перед возвратом (0–3600 секунд); сохраните в черновик.
3. В проверках резервных пар включите нужную очередь, укажите DNS-имя,
   до трёх HTTP/HTTPS URL без паролей и ожидаемые HTTP-коды.
4. Примените пакет. Убедитесь, что проверки всех пар подготовлены.
5. Только затем включите «Автоматически выбирать исправную пару» в активном выборе.
6. Проверьте переход при отказе и возврат; изучите журнал переключений.

Суммарно поддерживается до восьми проверяемых пар; независимые проверки FakeIP
недоступны. Для публичной очереди нельзя задавать рабочие/специальные тестовые имена.
Проверка должна отражать доступность нужного пути, а не только самого прокси-порта.

**Активный выбор меняется сразу**, без применения черновика. Ручное закрепление
сохраняется при отказе и перезапуске службы: неисправная закреплённая пара не
заменяется автоматически. Для возврата выберите «Без закрепления» и нужный режим
автоматики. При выключенной автоматике без закрепления сохраняется текущая пара.
Устаревшую форму активного выбора обновите перед действием.

Журнал переключений доступен из мониторинга; выберите очередь, сравните время,
причину и пару. История не заменяет проверку текущего выбранного пути.

## Особые DNS-ответы и редактирование резерва

В поле особого ответа выберите обычное разрешение, пустой успешный ответ (NODATA)
или отказ, доступный в списке формы; при необходимости ограничьте типы запросов
A, AAAA, CNAME, TXT, MX, SRV, PTR, HTTPS, SVCB. Проверяйте выбранный тип DNS
отдельно, поскольку успешный ответ A не проверяет запрет AAAA.

Резервы можно добавлять, удалять и переставлять кнопками либо перетаскиванием,
до 31 резервной пары в правиле. Без JavaScript для удаления очистите оба поля,
для новой строки сохраните форму. Если остался прежний список только выходов,
выберите DNS каждой пары и подтвердите замену прежнего списка. Пустой новый список
отключает резерв. Если все пары недоступны, совпавшее правило не передаёт трафик
следующему правилу. Проверки автоматики имеют свой меньший лимит — восемь пар суммарно.
