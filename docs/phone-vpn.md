# Подключить телефон к своему узлу по VPN

Это сценарий для телефона, который должен использовать ваш сервер дома или
вне дома. На сервере Фарватер принимает VPN-подключение, а телефон запускает
клиентское приложение. Веб-панель на телефоне для этого не требуется.

**Граница текущего alpha-выпуска:** новый входящий OpenVPN и его подключение с
реальным телефоном пока не подтверждены отдельной приёмкой в [матрице проверок](validation.md).
Ниже — понятный порядок подготовки и проверки, а не обещание готового VPN для
любой версии телефона. Если вам нужен уже принятый мобильный сервер, этот выпуск
такого результата пока не подтверждает; не переносите на него рабочую сеть до
испытания отдельного клиента. Для знакомства используйте проверенный локальный
proxy/DNS-сценарий из сетапа.

Пример ниже создаёт новый входящий OpenVPN на **полном Linux-узле**. Он использует
сервер внутри ядра, а не установку отдельного OpenVPN Access Server. Локальный
proxy/DNS-режим Mac этот сервер не включает. Работа с вашим мобильным клиентом
проверяется отдельно: статус alpha не является гарантией совместимости всех версий.

## Сначала подготовьте сервер

Если установлен только локальный узел на Mac, выполните [Linux-установку](linux.md)
на выделенной машине или сервере. После неё должны открываться HTTPS-панель,
«Изменения» и независимое восстановление. Ядро должно быть доступно.
Весь путь начального Linux-сетапа административный: нужны доступ к ОС, имя
сервера, сертификат панели и разрешённая административная сеть.

Подготовьте значения для входящего VPN:

| Значение | Где взять / пример |
|---|---|
| Локальный адрес сервера | IPv4 Linux-узла в домашней сети, например `192.168.77.10` |
| Внешний адрес | Публичное имя/IP вашего сервера, доступное с мобильной сети |
| Свободный UDP-порт | В примере `1194`; проверьте, что он не занят другим VPN |
| Свободная сеть VPN | В примере адрес сервера/пул `10.80.0.1/24`; сеть не пересекается с вашей LAN/VPN |
| Пользователь телефона | Собственный логин и пароль; отдельно от администратора панели |
| Сертификат/ключ VPN-сервера | Отдельная PEM-пара; подготовка ниже |

**Локальный** адрес используют устройства в той же сети. **Внешний** — вне неё.
Если сервер дома за роутером, настройте перенаправление выбранного UDP-порта на
IP сервера и разрешите его во внешнем firewall. Если провайдер использует CGNAT,
обычное перенаправление на домашнем роутере не даёт внешний доступ: потребуется
публичный адрес/достижимый узел. Точный путь меню зависит от роутера.
Не перенаправляйте наружу локальный HTTP-порт административной панели.

## Подготовьте отдельный сертификат VPN

На Linux-сервере, в домашнем каталоге административного пользователя,
создайте приватный каталог. Замените `vpn.example.org` своим именем:

```sh
mkdir -m 700 farvater-vpn-tls
(umask 077; openssl req -x509 -newkey rsa:3072 -noenc -days 365 \
  -subj '/CN=vpn.example.org' \
  -addext 'subjectAltName=DNS:vpn.example.org' \
  -addext 'extendedKeyUsage=serverAuth' \
  -keyout farvater-vpn-tls/server-key.pem -out farvater-vpn-tls/server-cert.pem)
```

Это пример отдельного самоподписанного сертификата **VPN**, не замена доверенного
HTTPS-сертификата панели. Фарватер закрепляет его отпечаток в выдаваемом `.ovpn`.
Содержимое `server-cert.pem` вводится в поле сертификата, `server-key.pem` —
в поле закрытого ключа. Откройте их локальным редактором, не публикуйте ключ.
После срока сертификат нужно заменить и выдать новые профили.
[Основание команды — документация OpenSSL](https://docs.openssl.org/3.0/man1/openssl-req/).

## Создайте вход и клиента в панели

1. «Устройства» → входящие подключения → «Другие протоколы» → OpenVPN →
   «Добавить подключение». Это **сервер для телефона**, не исходящий VPN.
2. Название `Телефон`, прослушивание `0.0.0.0`, порт `1194`, транспорт UDP.
   Локальный/внешний адрес задайте из таблицы без схемы и порта.
3. Адрес сервера и пул — `10.80.0.1/24`. Оставьте исходные MTU/лимиты для первого
   опыта; не разрешайте несколько подключений с одними реквизитами без нужды.
4. Вставьте PEM сертификат/ключ. Защиту служебного обмена оставьте `tls-crypt`,
   общий ключ пустым для генерации.
5. Включите «Направлять весь трафик клиента через этот сервер».
   В DNS клиентов укажите `10.80.0.1`: это адрес входящего сервера внутри VPN,
   на котором DNS обслуживается общей политикой. Дополнительные маршруты и
   поисковые домены для этого простого примера оставьте пустыми.
6. Добавьте клиента `phone` с собственным паролем, включите сервер и сохраните.
7. В «Изменениях» устраните ошибки, примените и подтвердите после проверки
   доступа и работающего сервера. Если ядро отклоняет тип/конфигурацию, остановитесь
   и сохраните сообщение: установка этой версии не готова к выбранному серверу.

Проверьте, что последнее общее правило выбирает доступный выход и DNS.
Телефон использует эти правила узла; создание входа не подключает автоматически
исходящий VPN. Если нужно отправлять его трафик ещё через другой VPN, сначала
создайте и проверьте тот выход, затем назначьте его правилам.

## Выдайте профиль и подключите телефон

1. Откройте созданный вход, карточку клиента `phone`. Скачайте `.ovpn` в режиме
   «Дома» для домашней сети или «Извне» для мобильной сети.
2. Передайте файл на телефон приватным способом. Он содержит параметры доступа.
3. Установите [OpenVPN Connect из официального источника](https://openvpn.net/client/)
   для iOS/Android. Нужен клиент с поддержкой `peer-fingerprint`:
   старые OpenVPN Connect 3.3 и ниже не подходят для этого примера. Это ограничение
   [описано OpenVPN](https://github.com/OpenVPN/openvpn/blob/master/doc/man-sections/example-fingerprint.rst).
   В приложении откройте профили → добавление → импорт файла,
   выберите `.ovpn` и подтвердите импорт. Названия кнопок могут различаться по версии;
   [официальная инструкция импорта](https://openvpn.net/connect-docs/import-profile.html).
4. Если клиент запросит логин/пароль, используйте `phone` и пароль VPN-клиента,
   не пароль администратора панели. Включите профиль, разрешите VPN-подключение ОС.

## Проверьте результат

Для внешнего профиля выключите Wi-Fi на телефоне и используйте мобильную сеть:
так проверяется внешний адрес, а не домашняя доступность. В клиенте должен быть
статус подключения, а при открытии сайта — переданные/полученные данные.

На Linux-сервере выполните именно запрос через вход Фарватера:

```sh
curl --fail --show-error --max-time 15 --noproxy '' \
  --proxy socks5h://127.0.0.1:2081 https://api.ipify.org
```

Затем на телефоне с выключенным Wi-Fi включите внешний профиль и откройте
`https://api.ipify.org`. Адрес должен соответствовать серверному выходу.
Если телефон до VPN уже использует тот же выход, сравнение IP не различает пути. Если включено правило для этого сервиса, оно влияет на результат.
Проверьте обычный сайт и нужные рабочие ресурсы отдельно. Один IPv4-тест не
доказывает отсутствие IPv6-обхода; проверяйте семейства, предусмотренные вашей сетью.

Для домашнего профиля совпадение публичного IP недостаточно: телефон и сервер
могут выходить через один роутер без VPN. Для различимого теста выберите внутреннюю
службу в вашей сети, доступную только через сервер, либо на Linux-сервере запустите
`sudo tcpdump -ni ИНТЕРФЕЙС udp port 1194` на фактическом внешнем/LAN-интерфейсе.
При включении профиля и новом запросе должны появляться пакеты от IP телефона,
а в приложении — статус подключения и рост счётчиков. Одновременно проверьте
полезный трафик, чтобы не принять одни попытки соединения за работающий туннель.
Если `tcpdump` отсутствует, установите его пакетным менеджером или сначала
проверьте внешний профиль с мобильной сети; название интерфейса найдите командой `ip -br address`.

Если соединение не устанавливается, сначала проверьте внешний адрес и UDP-порт,
затем реквизиты и сообщение клиентского приложения. Если VPN подключён, но имена
не открываются, проверьте DNS `10.80.0.1` и общую политику. При ошибке сертификата
сверьте профиль с текущим серверным сертификатом; не отключайте проверку.

Отключите профиль на телефоне, чтобы вернуть обычное подключение телефона.
Для отзыва доступа выключите клиента в редакторе входа, сохраните и примените.
Изменение/удаление входа влияет на всех его клиентов, поэтому проверьте состав
пакета прежде, чем подтверждать.
