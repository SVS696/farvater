# Панель управления сетью

Веб-панель для туннелей, DNS, правил маршрутизации, резервных выходов, клиентов WireGuard и мониторинга. Сетевые службы работают на Linux. Панель управляет их конфигурацией и не требует определённой модели роутера или личной топологии.

## Настройки вместо личной топологии

1. `OKOPY_STATE_DIR` задаёт приватный каталог панели. `auth.json` содержит администратора, `policy.json` — черновик политики. Файлы принадлежат пользователю панели и имеют права 0600, каталог — 0700.
2. `OKOPY_CANDIDATE_CONTROL=local` выполняет фиксированную служебную команду на той же машине. Права выдаются отдельным правилом sudo; пароль root в веб-панели не нужен. `OKOPY_HEALTH_SOURCE=local` получает местные снимки мониторинга.
3. `OKOPY_CANDIDATE_CONTROL=ssh` и `OKOPY_HEALTH_SOURCE=ssh` используют единый `server.json` в каталоге состояния. Путь можно явно заменить через `OKOPY_SERVER_CONNECTION`. Никаких предустановленных личных SSH-алиасов или путей к Mac нет.
4. Для SSH адреса и реквизиты редактируются в «Помощь → Доступ панели к серверу». Все основной и резервные адреса должны вести к одному серверу. SSH проверяет известный открытый ключ. Запись не повторяется после неопределённого ответа; чтение допускает резервный адрес.

Схема `server.json`, без действительных реквизитов:

```json
{
  "version": 1,
  "targets": [
    {"host": "server.example.com", "port": 22, "username": "operator", "identity_file": ""}
  ],
  "sudo_password": ""
}
```

Пустой пароль означает настроенное администратором sudo без пароля для служебной команды. Пустой `identity_file` использует ключи пользователя SSH. Неизвестные ключи сервера автоматически не принимаются. SSH-ключи, доступ sudo и системные службы подготавливаются при установке, а не этой веб-формой.

## Работа с правилами

Список доменов редактируется текстом и визуально, синхронно при вводе. `# Заголовок` образует сворачиваемую группу. Сам домен, маска всех поддоменов и отдельные поддомены — разные условия. Комментарии не становятся сетевыми правилами.

«Сохранить черновик» записывает изменения в постоянное состояние панели. Проверка и применение сетевой политики выполняются отдельно. При несохранённых правках формы панель предупреждает перед уходом, браузер — перед обновлением или закрытием вкладки. Содержимое форм и секреты не записываются в localStorage.

## Перенос настроек

В «Резервные копии → Настройки панели» доступны экспорт JSON, предварительная проверка импорта и подтверждаемая замена черновика. Сетевые службы не меняются до отдельного применения. Этот файл содержит правила, выходы, DNS и фильтрацию; самостоятельные профили VPN-служб и ключи входящих клиентов переносятся своими стандартными форматами. Файлы экспорта могут содержать секреты.

## Проверки разработки

Установите зависимости `requirements-lock.txt` в отдельное Python-окружение. Целевые проверки для транспорта и редактора:

```sh
python -m unittest test_server_connection test_candidate_remote test_health test_domain_document test_monitor_dashboard test_connection_exchange test_policy_exchange
```

Нативные сетевые проверки требуют отдельного Linux-стенда и необходимых протокольных утилит. Их нельзя запускать на рабочем сервере без понимания конкретного сценария и отката.
